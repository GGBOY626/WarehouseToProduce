# 生产任务关联与分批回仓

## 登记页面

- 新增、编辑流转只提供产品备注，用于补充情况和异常描述；移除整单备注和异常多选控件。
- 历史整单备注和异常数据仍保留，编辑已有记录时原样提交，详情和 PDF 继续可追溯。新记录不会创建这些旧字段。
- 生产任务选择位于产品、数量和照片之后。不选择任务仍可保存。
- 一张流转单关联一个任务。含多个产品时，所有产品必须匹配同一任务；不同任务的物料需分单。
- 按产品 ID 匹配，不按名称猜测，不合并不同编码、批次或历史重复产品。

## 状态及筛选

| 流转类型 | 产品要求 | 可新关联的任务状态 |
| --- | --- | --- |
| 仓库 → 车间发料 | 本单全部产品都在任务所需物料中 | PREPARING（备料中） |
| 车间 → 仓库退料 | 本单全部产品都在任务所需物料中 | PREPARING / IN_PROGRESS / COMPLETED |
| 车间 → 仓库成品 | 本单产品为任务明确设置的成品 | PREPARING / IN_PROGRESS / COMPLETED |

取消任务不接受新关联。已完成任务仍允许补登成品及退料。进入生产中或已完成后，需要继续发料可点击“重新开启备料”。

状态继续人工管理，不由数量推断。页面支持备料中直接“标记已完成”，无需先点开始生产。已关联记录可在保留原产品、方向、退料类型和任务的情况下编辑数量或备注，即使原任务已完成、取消或调整过需求也不清除旧关联；换产品或换任务须重新校验。

## 产量和耗用

任务可设置一个成品产品和计划产量。原所需物料表就是本次生产的配比依据，不新增通用配方系统。

- 备料进度沿用原计算：有效发料 − 有效退料，与所需数量对比。
- 生产完成率 = 已关联的有效成品回仓数量 ÷ 计划产量。进度条最高 100%，实际回仓数量不截断，超产另行显示。
- 预计物料耗用 = 已回仓成品数量 × 所需物料数量 ÷ 计划产量，最多保留 6 位小数。
- 这是按配比预计耗用，不是实测消耗；未计入废品、损耗、在制品。实际发料和退料始终分开显示。
- 成品回仓按产品基础单位登记：可按盒，也可按个，不用运输箱规推断 30 个装一盒的生产关系。
- 未知数量不视作零产出，单独提示未计入数量；编辑、作废、删除、改关联后实时重算。
- 多装箱规格、满箱、尾箱、散装沿用已有总数量，不重复计算或通过余数推断包装。
- 有成品回仓历史时不能移除或更换任务成品。调整计划产量或物料需求会按新计划重算进度和预计耗用。

## 接口

新增轻量筛选接口：

```http
GET /api/production-tasks/linkable?productIds=1,2&direction=WAREHOUSE_TO_PRODUCTION&returnMovement=false
```

返回 `id, productName, batchNo, status`，仅匹配任务；无需加载各任务全部流转历史。保存流转时复用同样规则校验，不能绕过前端关联无关产品。

复用既有状态接口，不重复新增同功能路由；写入仍要求管理员登录：

```http
PATCH /api/production-tasks/{id}/status?status=COMPLETED
```

任务新增/编辑接口增加可选 `outputProductId`、`targetOutputQuantity`，必须同时提供或同时为空。成品须属于车间 → 仓库并有明确单位。响应增加 `output`（成品、计划量、累计回仓、完成率、未知数量条数），各物料增加 `estimatedUsedQuantity`。原备料进度字段语义不变。

## 数据库与兼容

Flyway `V12__add_task_output_plan.sql` 仅为 `production_task` 新增两个可空字段：

- `output_product_id`：产品外键，禁止删除被引用的产品。
- `target_output_quantity`：计划产量；约束要求两列同时为空或同时有效且产量大于零。

旧任务两列均为 NULL，不自动关联成品、不转换旧数量、不改任务状态。旧任务需要在编辑页明确设置成品和计划产量，才能新关联成品回仓。已有流转、整单备注、异常、任务需求和 TR 编号全部保留。无需调整本地 application.yml 或数据库账号密码。

## 验证场景

1. 建任务 A001，成品单位“盒”，计划 500 盒；物料关节饮 15000 个、内盒 500 个、外盒 500 个。另建只需要其他物料的任务。
2. 发料选择关节饮，只看到需要它且备料中的任务。不同物料不匹配的任务不出现。新增重复箱规行不影响匹配。
3. 发齐上述物料，在任务仍为备料中时回仓 100 盒，选择 A001。备料 100%、生产 20%；关节饮预计耗用 3000 个，内外盒各 100 个。
4. 再回仓 400 盒，生产 100%，累计关节饮预计耗用 15000 个，内外盒各 500 个。状态仍由人工确认。
5. 若成品以“个”管理，计划产量填写 15000、回仓 3000 个，同样是 20% 和包装各 100 个。
6. 备料中直接点“标记已完成”；任务从发料候选消失，成品回仓及退料仍可补登记。取消后从全部新关联候选消失。
7. 编辑/作废/删除回仓或退料记录，核对累计产量、预计耗用及备料缺口重算；未知数量明确提示。旧记录不被重写。
8. 运行 Java 21 下 `cd backend && mvn test`、`cd frontend && npm test && npm run build`。

已在隔离 H2 中跑集成测试和浏览器登记流程，并在独立 MySQL 8 实例验证 V1–V12 迁移及旧任务保留；未在用户业务数据库上运行测试。
