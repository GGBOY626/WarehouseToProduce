# 一个产品维护多个物料批次

产品管理按“仓库 → 生产车间”和“生产车间 → 仓库”分别查看。物料编码的标签统一使用“物料编码”。产品下可保存多个物料批次，每行一个；登记时输入新批次也会保存到该产品，不需要创建新产品。

登记流转和创建任务时，每项物料单独选择批次。单一批次自动带入，多批次不默认选择。可用“添加同物料规格 / 批次”登记同一产品的另一个批次。物料批次与可选的“区分批次”是两个字段，后者仍用于同一物料批次内部进一步区分外盒。

## 多个默认每箱数量

产品的“默认每箱数量（可设置多个）”可填写 `500、1000、1800`，用逗号、顿号或空格分隔。原来的默认数量与常用规格统一显示，复用现有 `product_carton_spec`，无需新增迁移。

- 只有一个规格时，新增出入库自动带入；多规格时留空，通过规格按钮选择，也可输入临时规格。
- 满箱记录未选择规格时，前后端都阻止保存；仅登记尾箱或散装不要求选择满箱规格。
- 添加同物料新明细、复制记录后，多规格需重新选择；编辑已有明细保留原规格，产品设置变更不会重算历史记录。
- 验证：预设上述三个数量，新建出库或入库，选择 1800 并填 2 满箱，应为 2 箱、3600 个；仅填 1 尾箱 × 3 个及散装 2 个，应为 1 箱、5 个。
- `CartonSpecSelectionIntegrationTest` 与 `frontend/tests/cartonSpecs.test.mjs` 覆盖规格选择、兼容旧默认值、两方向校验和尾箱/散装免选规则。

## 数据迁移 V15

- 新建 `product_material_batch` 批次表，收集产品已有批次和流转记录实际保存的批次，并保留常用箱规。
- `product.merged_into_id` 记录重复产品归属。仅合并名称、物料编码、方向、计量单位、数量是否确定一致的产品；优先保留启用产品，否则使用最早 ID。重复产品保留为停用的历史关联，不删除，不改写历史外键和快照。不同方向不合并。
- 产品启用唯一约束加入方向，允许同名同编码分别用于两个方向。
- `movement_item.material_batch` 保存每项实际批次；旧记录从原单据批次复制，不根据产品当前批次推断。未迁移记录读取时仍兼容旧单据字段。
- 生产任务目标增加 `material_batch`，唯一约束改为任务、产品、批次；成品计划增加 `output_material_batch`。
- 旧任务未限定批次的继续使用原统计口径，不自动给旧任务指定批次。新建任务遇到多批次必须选择。任务已有成品回仓后不能更换成品及其批次。
- 满箱、尾箱、散装、实际总数、流转单编号、记录照片均不改变。

随新版本后端启动，由 Flyway 执行 V15。测试使用独立 MySQL 数据库，未连接或迁移使用者的实际数据库。本地 `application.yml` 不包含在本次提交中。

## 接口与主要实现

- 产品 DTO 新增 `materialBatches`，保留旧 `materialBatch` 字段兼容旧客户端。批次增量保存，已有批次不因编辑时省略而丢失。
- 流转明细请求与响应新增 `materialBatch`。旧客户端仍可传单据级 `manufactureLot`；新客户端逐项传入。统计、搜索、详情、PDF 共用实际明细批次。
- 任务目标请求新增 `materialBatch`，任务保存请求新增 `outputMaterialBatch`；响应的目标及成品中也提供批次。
- `POST /api/production-tasks/linkable` 接收 `{ direction, returnMovement, items: [{ productId, materialBatch }] }`，筛选产品、批次、状态均匹配的任务。保存时再次验证。保留旧 GET 接口。
- 主要文件：后端 `product/*`、`movement/*`、`production/*`、`report/PdfReportService.java`；前端 `ProductView.vue`、`MovementFormView.vue`、`ProductionTaskForm.vue`、共享 `MaterialBatchPicker.vue` 以及列表、详情和任务摘要组件。

## 验证方法

1. 同方向同名同编码的 A001、A002 两份旧产品迁移后只出现一个可选产品，批次列表包含两者，旧流转详情和数量不变。另一方向的产品仍独立。
2. 选择多批次产品，确认批次未默认选中。分别登记 A001、A002 后，列表及统计各自展示；修改其中一项批次不影响另一项。再输入 A003，保存后产品批次列表应多出 A003，产品数量不增加。
3. 创建任务，分别填写同产品 A001 需 20、A002 需 30；发出 10 和 3 后，进度分别为 50% 和 10%。其他批次不能关联该任务。成品 F001 的任务不能关联 F002 回仓。
4. 核对旧的“15 箱＋散装 3 个”：仍为 15 箱、15003 个，不转换为尾箱。PDF 应分别显示各明细批次，继续保留原包装数量和区分批次。
5. `backend` 使用 Java 21 执行 `mvn test`；`frontend` 执行 `npm test` 和 `npm run build`。

新增 `MaterialBatchIntegrationTest` 覆盖新增、编辑、搜索、统计、任务匹配、进度、合并关联和历史散装兼容；`PdfReportServiceTest` 覆盖同单不同物料批次的导出。
