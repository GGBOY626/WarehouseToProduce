# 生产任务、批次和实际产出

## 使用方式

1. 新建任务即为“进行中”，每种仓库 → 车间物料只填写一行需求总数，不再指定需求批次。不同批次的发料合计计算，任务中可展开批次及区分批次明细。
2. 可在创建时或以后编辑时选择“出货物料 / 成品”（车间 → 仓库），指定主料，填写每箱盒数、每盒包含的主料数量，以及成品入库数量按盒还是按单件登记。计量口径应与该成品的实际库存登记方式一致，不会修改产品基础单位。
3. 成品回仓先选择产品，再选择匹配的生产任务。关联后自动带出任务箱规；尾箱按实际盒数填写，例如 1 尾箱 × 3 盒。真正散装按产品基础单位填写，不计入箱数。
4. 退回物料勾选“这是退回物料”，使用仓库 → 车间的产品，匹配任务所需物料；退料扣减净发料，不增加成品产量。
5. 任务由用户“标记已完成”，可“重新开启任务”。历史备料中、生产中均展示为进行中；历史取消状态保留读取。完成后停止新增发料，仍允许补登记成品和退料。数量达到 100% 不会自动结束任务。
6. 生产任务和产品管理位于顶部中间，与退出按钮间隔摆放。任务列表和详情每 15 秒刷新可见页面，切回窗口也更新；编辑过程中不刷新表单。

## 数量口径

- 净发料 = 关联的有效发料 − 有效退料；作废记录不计入。
- 每种物料备料进度 = 净发料 ÷ 需求总数，显示上限 100%。任务总体备料进度沿用各物料进度的平均值，不把不同单位的数量相加。
- 回仓按盒登记：折算主料数量 = 已知回仓盒数 × 每盒数量。
- 回仓按单件登记：折算主料数量 = 已知回仓单件数量。
- 生产完成度 = 折算主料数量 ÷ 主料实际净发料，显示上限 100%，与计划需求无关。
- 损耗率显示为 100% − 生产完成度；超出净发料时损耗显示 0%，另提示核对。零净发料、负净发料或主料/回仓有不确定数量时不显示百分比，避免假精度。
- 进行中的差额可能是在制品或尚未登记的回仓，页面标为“暂估损耗率”；结束任务并补齐记录后核对最终损耗。
- 内外盒等辅料单独显示已发、已退、净发、欠料，以及按计划配比折算的预计耗用，不与主料混加。

例如需求 5000 个内盒，22677 批发 2000、22678 批发 3100，合计 5100，备料 100%，批次明细仍分别保留。主料计划需求 20000，实发 10000，备料为 50%；回仓折算 9000，生产完成度 90%、暂估损耗 10%；若回仓折算 10000，生产完成度为 100%。

28 盒/箱 × 30 条/盒：按单件登记时一满箱为 840 条，1 尾箱 × 3 盒为 90 条；按盒登记时分别为 28 盒和 3 盒，计算产出时再乘 30，不会重复换算。

## 数据与接口

- V16 只为 `production_task` 增加可空字段：`output_boxes_per_carton`、`output_units_per_box`、`output_quantity_basis`、`primary_material_product_id`，并添加外键和完整性校验。不修改流转数量、历史批次、单号或产品计量单位。
- 旧任务缺少主料/换算设置时继续显示原计划回仓进度，不能自动猜测损耗。可人工补充配置；已有配置且已有回仓后，成品、主料和换算方式被锁定，避免重新解释历史记录。
- 旧任务分批次的需求行在读取时按同产品合计，编辑保存时归为一行；历史发料和退料记录不改写。
- 保存任务新增字段：`outputBoxesPerCarton`、`outputUnitsPerBox`、`outputQuantityBasis`（`BOX` / `UNIT`）、`primaryMaterialProductId`。包装模式下计划产量可省略，由主料需求换算，仅用于计划配比。
- 任务匹配接口保留原请求格式，但不再按批次限制。正常回仓仅匹配任务成品产品；退料匹配所需物料；发料还要求任务进行中。
- 响应目标新增 `batches` 明细；成品新增净发主料、折算数量、盒数、生产完成度及损耗率。旧字段保留兼容。

## 验证

`TaskYieldIntegrationTest` 覆盖跨批次合计、实际投入作为分母、手动完成/重新开启、28×30 包装和 3 盒尾箱、退料、作废、零/未知数量、旧任务编辑、后补成品及非法配置。`taskPackaging.test.mjs` 验证前端盒/单件换算不重复计数。

已在独立 MySQL 数据库演练 V16，迁移前后历史明细数、箱数、总数量一致；浏览器核对手机导航、任务进度和实际尾箱登记。测试库与用户实际数据库隔离，本地 `application.yml` 不在提交中。
