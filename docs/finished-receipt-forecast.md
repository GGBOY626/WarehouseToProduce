# 预计成品回库与 V21 升级

## 使用与口径

1. 在成品产品管理中维护包装层级：如基础单位“个”、22 盒/箱、30 个/盒，可选 40 箱/托盘。多种规格须明确选择，不从原料箱规推断。
2. 编辑生产任务，选择成品和主料，确认任务成品箱规。预计成品默认按主料净发量 1:1 计算，无需另配产出比例。按盒登记（BOX）时，主料基础数量先除以任务保存的每盒内装数；按单件登记（UNIT）时直接使用净发数量。请确保主料基础单位对应成品内装单件。
3. 净发量扣除退料；此为按主料折算的理论产量，未计损耗或其他物料瓶颈。缺少成品、主料或箱规的旧任务仍显示“待配置”，已有完整信息的旧任务自动采用 1:1。
4. 已回库只统计本任务关联、ACTIVE、生产车间到仓库、非退回、成品 canonical ID 匹配的记录。产品名称不参与匹配；同名物料、未关联、其他任务、作废和已删除记录不重复计入。
5. 待回库 = 预计产出 − 已回库。负差额显示为“超额回库”，回库百分比可超过 100%。未知发料或回库数量显示待核对，不把已知部分当作完整数量。预计为零时百分比为“—”，已有回库仍显示超额。
6. 按任务箱规折合整箱、余盒、余基础单位；托盘折合整托盘、余箱及尾数。采用整数/有理数运算，不四舍五入数量。仅百分比显示到两位小数。折合箱数不同于包含尾箱的实际占用箱数。
7. 原备料进度、原生产完成度、计划需求和状态规则未更改。产品默认包装修改不会重写任务已保存的包装和托盘规格，也不修改流转历史。

## 数据库升级

V21 仅增加四个可空字段：product_box_packing.cartons_per_pallet，以及 production_task 的 output_cartons_per_pallet、yield_material_quantity、yield_output_quantity。不回填猜测值，不删除数据，不变更已有唯一索引或外键。

V21 已发布，不修改迁移历史或删除旧字段。`yield_material_quantity` 和 `yield_output_quantity` 为兼容已升级数据库保留，但不再参与计算；即使历史任务存有配比，也统一按 1:1 重新计算。V1–V20 不作修改。

MySQL DDL 部分执行时，V21 会逐字段检查是否存在，可安全继续完成剩余字段。若 Flyway 已留下失败历史，先检查失败日志、四个字段的实际类型、原表数据及 flyway_schema_history；确认仅为本迁移部分执行后，由维护人员针对该环境运行 Flyway repair 清理失败记录，再运行 migrate。不要删除历史或重建业务库；也不要用 repair 隐藏其他迁移的校验差异。

## 自动化验证

`FinishedReceiptForecastTest` 覆盖默认 1:1、部分/多次回库、未关联记录、同名跨类型产品、退料、作废/删除、零发料、未知数量、超额、盒口径、箱/托盘余数及原进度独立性。

可选 MySQL 测试仅连接 `127.0.0.1:33321` 的独立测试实例，使用两个全新空库 `forecast_upgrade` 和 `forecast_boot`，无密码本地测试账户 root。禁止在业务实例运行这两个测试。

设置 `FORECAST_MYSQL_TEST=true` 后运行 `mvn -Dtest=ForecastMigrationMySqlTest,ForecastMySqlStartupTest test`，验证 V20 部分执行恢复、重跑、全新升级至 V21、Spring Boot 启动、Hibernate validate 和箱规持久化。不设置此环境变量时跳过这两个可选测试。测试不删除数据库，重复运行应使用重新初始化的独立测试实例。

前端 `npm test` 和 `npm run build`；可用 `node tests/fixtures/task-list-server.mjs` 在 5192 端口检查真实构建页面的示例状态，数据全部为模拟数据。
